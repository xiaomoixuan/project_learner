# 教材验收执行协议

这是启用interview时的验收状态、证据记录和修补流程的单一规范。是否启用由主Skill的按需策略决定；未启用不能填写或宣称独立通过。深度标准解释教到什么程度，本文件规定怎样证明正文达到了要求。检查对象是教学方案的完整性、可执行性和可学性，不是核实用户是否亲历；教学模拟记录可以作为方案中的材料，不能称为企业真实证据。

## 1. 先确定要检查什么，再看作者写了什么

验收同时检查顺着正文能否学会，以及连续追问能否回答。先按[六板块规范](document-guide.md)及 [教学组织方法](teaching-method.md) 检查正常阅读，不允许专家通过搜索、跨章拼表或补行业先验来代替学习。即使所有信息散落在文内，主要工作缺少必要概念、连续演示或判断解释，也不能完成验收。六个板块的职责、小节主题、前后连接及自然语言同样必须成立；不能把补题逐项粘成新章节。

主作者从简历涉及的知识、动作与结果，以及完成项目所必需的依赖建立内部覆盖清单，不要求逐句解释或按清单排列正文。检查者只从允许的原始材料独立推导问题，不接收作者清单。每项有稳定 ID、原始依据、关联工作/规则/结果、项目内边界。尚未写进目录的依赖不能因此从清单消失。JD 不适配项标明本项目可覆盖、可延伸教学或需要别的项目，不能擅改原项目。

出题代理的项目材料只能是原始简历或忠实转录，以及用户实际提供的JD。系统可指定镜头、用户选定项目与输出要求；禁止提供主作者补建的情境、范围设定、知识清单、目录、正文、自评或其他问题。使用不继承作者历史的新上下文，依据原材料独立生成追问。启用后，由三个独立上下文的子代理分别读取同一 [内部 interview 模块](../internal/interview-auditor/SKILL.md)，以项目与个人判断、操作与证据、初学者迁移与一致性三个互补视角执行。岗位改变问题和证据形式，不必改变独立检查的职责。并发不足时分批运行独立实例；未能调用子代理时可以做临时自查，但多代理验收仍标为未完成。

问题及子问保存稳定 ID 后冻结，再交完整正文和版本给原提问者。三个实例在冻结前不读彼此问题，冻结后可汇总查漏。不向出题阶段发送任何作者情境摘要。问题如因信息不足产生，正文应在统一教学方案中补教并解释；不能据简历没写就认定未做，或事后缩范围让缺口消失。

问题必须源于当前项目。用户要求回答的适用题及子问保留原 ID；难度示例转换后记录来源关系。多个问题可共用正文依据，但不得因合并丢掉回答义务。范围外提问保留并核查正文能否解释边界及合理下一步，不得由作者以“不适用”直接删掉难题。题目数量服从核心工作和决定，不设统一配额。


### JD后补与输入批次

先无JD时照常冻结原始批次。用户随后实际上传JD，另存“原简历+该JD”的新输入批次，同三位实例只据新增原始材料追加问题，不接收作者解释或其他题。新批次使用独立case_id与新题ID，保留旧批次及原题；不把不同input_sha256强行链接成同一问题历史。每批内部仍沿用原有questions/ledger结构及previous_questions、previous_ledger。最终对每批分别运行完整性核对，全部账本绑定同一最终正文，任一批未闭合不能交付。材料更新后只修补受影响教学和问题，不整本无故重写。

## 2. 真正作答，而不是检查关键词

每个问题保存以下记录，Markdown 或等价结构均可：

| 字段 | 必须记录的内容 |
| --- | --- |
| ID 与原题 | 完整问题；同题的多个要求分开判定 |
| 来源与范围 | 简历、流程、岗位判断或新发现的依赖；项目内/边界问题 |
| 正文依据 | 具体标题或锚点及实际句意，不能只给整章链接 |
| 实际答案 | 检查者仅依据正文写出的回答或逐步执行轨迹；目标角色行动用“我” |
| 结论边界 | 当前材料能支持什么；哪些确属未实施的下一步 |
| 状态与断点 | 通过、过浅、缺失、冲突之一；失败发生在哪个具体子问 |
| 修补与复查 | 正文修改位置、关联引用、复答结果及受验版本 |

四状态保持如下含义：

- **通过**：读者按正文顺序已学到回答所需概念、操作和判断，主要工作有连续讲解与示范；每个子问均可从正文回答，推导没有引入新的关键前提；规则能得到明确的动作或判定，证据足以支持正文实际声称的结论。
- **过浅**：有概念或原则，但缺具体材料、步骤或应用过程；只有表格/字段/编号等资料，缺少就地解读和动作之间的解释连接，也属于过浅。回答仍是“应检查、需分析、可能这样”。
- **缺失**：必须新增关键规则、记录、数据、职责、时点或论证才能作答；没有到达最终判定点的处理规则也属于缺失。
- **冲突**：正文不同位置对同一条件产生不兼容的动作、数字、版本或结论。

### 从问题答案回到应修的教学位置

实际答案涉及工作时，检查者从正文提供的材料走到一个具体中间结果和可用产物，说明关键操作与判断依据；只复述作者的结论、填字段名或引用前后成品不算执行轨迹。背景和原理问题按其学习职责解释，不硬造交付物。

缺口记录在现有gap/repair中写清：当前任务、已读到的材料、第一次不能继续的位置、缺的是材料/操作/判断/产物/交接中的什么、应补写的标题及段落。正文已有内容但读者无法连接时，先改当下的解释与顺序；不要默认再加一章或问答。复习路线可引用这些教学位置，完整验收记录仍另存。

各主要工作分别检查；同一案例无法覆盖的新机制要另给必要材料。深写标准不固定示范案例的步骤、小标题、数量或参数；发现这些内容被机械套给其他岗位，也按实际跳步或不适配记录。修补后用原材料复走，再检验受影响的相邻条件。

合理推导只使用正文明确的前提和一般算术/逻辑。例如从两个集合推导交集可以；自行补一个超时阈值、评分点、假设已完成的实验不可以。专业机制正确性另作事实核查；公开来源只能验证原理，不能替正文补项目设定。不得用平均分抵消任何核心子问的未通过。

## 3. 三类最容易被概述掩盖的证据

### 可执行规则与观测协议

对任务执行、评分、研究标注、状态转换等关键规则，固定输入、前置状态、版本、操作者、判定时点、允许分支、退出/中止、缺失或 unknown、争议裁决、输出和下游动作。给一份填好的输入及完整处理结果，让另一位执行者无需新增规则即可复判。

多轮任务给每个计分点唯一标识与所属轮次；写清早退、超时、跳步、重复操作是否继续及如何计分。重复观测区分计数单位，不能只有分母总数。研究结论应能追到当时的刺激材料和观察记录，不能拿改版后的页面解释旧版测试。

检验方法是实际走一次：正常输入，再换一个会改变结果的条件，列出每一步和最终结论。发现两种都符合正文的判法却给出不同结果，判缺失或冲突；不能因为公式正确就通过。

### 已作决定与残留范围

当教材说“我推荐 A、团队批准 B、版本进入试点”时，要能从正文找到当时的备选、输入材料/版本、判断标准、我的分析与交付、决定人、最终动作及其代价。门槛应与可能发生的用户后果和资源约束相连。

相邻版本结果都过线时，解释为什么仍继续迭代、何时作出何种决定。允许选择“前一版已可交付，后续属于另一项改进”等合理教学设定，但必须明确。没有真实记录时补一份教学记录，而非把已经作出的决定写成“未知”。

以缩小范围接受残留时，全部会影响该决定的残留要对应到触发条件、是否仍在范围内、隔离/兜底/修复依据和验收结果。可以合并具有相同机制及处置的条目，但保留 ID 与覆盖范围；少数代表案例不能证明全部已隔离。

简历未提及不代表未实施；阶段未给出时自主补成相容的完整教学过程。只有用户明确限制或统一方案确实设定为未来的验证才保持未来身份。一个明确停在“暂不批准，缺材料 X，下一步 Y”的教学决定也可以通过，只要与整篇交付阶段一致。

### 干预、证据与结果

从改动发生的环节画出到结果的最短因果路径，说明每条连接的机制和材料。指标位置在改动之前且没有明确反馈机制时，只能作为背景或可比性信息。每个关键选择至少展示能解释选择的差异材料；汇总变好不能替代逐例诊断，也不自动证明因果。

## 4. 反例与初学者迁移

反例围绕会推翻结论的条件设计，不限于技术故障：重复/乱序/部分失败/持续失败、观察缺失、版本变化、权限变化、协作者减少、任务学习效应、证据解释不同等，按岗位选择。

例如后台批处理必须推演某些记录持续失败时，其他正常记录是否仍有进展；定性研究应检查同一观察的其他解释以及测试材料是否实际施加所说的改动。这些是发现方法，不是通用必答题。

C 镜头先从头顺序读，不看覆盖表、不先检索后文；在主要任务第一次需要某个概念或操作处，记录当时能否理解我为什么做、拿什么、怎样下手、怎样判断和交给谁。出现跳跃时标出第一次断点，按过浅/缺失回填讲解；不能仅因后来能找到答案就通过。然后再执行迁移。初学者检查先明确完成核心任务所需的概念，再给一个正文没有直接演示过、但属于既定规则范围的变体。让检查者按正文产出小交付（状态轨迹、标注、问题单、设计判断或计算），逐步指明依据。参考解的关键推导留在正文或紧邻教学例中；不能藏在答案附录。无法迁移时补先修概念和推导，不能用“读者应有基础”豁免目标读者。

## 5. 修补一次，复查全部关联位置

写作时维护轻量规则/决定/数字登记：ID、唯一说明位置、引用位置、影响的工作与题目。无需给每个普通句子编号。修补时：

1. 改正文中该规则的完整说明；索引和答案不能先补出正文没有的内容。
2. 用搜索和登记定位它在全貌、流程、样例、个人工作、结果口径、讲述、表格和图中的引用。
3. 对全部相关位置用同一个输入/反例复查；版本、顺序、分母、状态一致才算同步。
4. 原检查者按修改后的正文重新回答原题；其他受影响题重新判定。新增机制引入新的重要依赖时追加问题，保留旧 ID。

保留修补前状态与新结果，不把失败历史覆盖成从未出错。已通过但正文改动影响其依据的题不能沿用旧通过结果。

## 6. 完成条件与交付

完成需要：三个独立 interview 实例的身份、视角、输入及问题版本可追溯；核心工作与重要决定有来源可追溯；所有冻结及追加问题的每个子问均通过；范围外问题已有明确边界答案；必要执行变体和初学者迁移有实际轨迹；修补后的跨章节回归无未解决问题。任何检查者仍判未通过时不能按多数票或平均分放行；记录双方正文依据，修补歧义后复判。题数、字数、链接数量和模型自信度均不能代替这些条件。

闭合既定范围后停止扩题；不为无限未知条件扩写整个行业。遇到工具中断或资源不足，保存统一设定、正文、问题、答案与待修项后继续；未完成时如实标为未验收，不得删题、放宽标准或声称通过。用户不需要逐阶段确认。

交付以完整第一人称教材为主，末尾提供可读的复习路线和配套验收记录链接。完整实际问题/子问覆盖索引、答案、正文定位、状态、版本及修补过程保存为配套验收文件；不用哈希、原始ID、状态行和裸HTML锚点打断学习。没有尾部审查索引时，对整份教材原始字节计算摘要；兼容既有索引标记的计算方式仍见内部记录契约。正文修改后必须重新验收。配套记录不能补藏正文没教的关键答案；不承诺真实用户已掌握或真实面试必然通过。

## 维护实验与策略变更

用户要求检验interview价值时按[对照协议](comparison-protocol.md)冻结直接生成版与改进版，另由新上下文代理盲评。此处三个问者的身份、题集和历史仍按原契约记录；额外比较者不冒充其中之一，也不修改问题。只有使用interview的运行才要求三镜头全部闭合；默认是否强制由有证据的维护策略统一说明，不能在普通执行中临时省略。
