# 深度：能够解释和判断

手册的深度以陌生求职者学完能理解项目、解释设计和应对追问判断，不以能否照着代码或日志复做实现判断。结构见[六板块规范](document-guide.md)，写法见[教学方法](teaching-method.md)。

主要功能应让读者明白用户目的、处理过程和结果如何相连。核心机制应让读者解释它解决什么问题、怎样工作、为什么采用、代价与适用条件。个人工作应让读者说清我如何从需求走到方案和验证，遇到什么困难，怎样作选择，哪里值得保留，哪里还需改善。

空洞概括和实现细节堆积都可能不够深。只有“优化检索、效果提升”看不出做法；有大量参数和状态，却不知道它们服务哪个功能，同样没有教懂。具体例子应展示关键认识或决定怎样产生，不强制每项都做操作回放、小交付或字段填表。

顺序阅读后，尝试用自己的话讲通项目，再沿一项功能解释每一环节如何衔接，并处理一个会改变结果的相邻条件。若能说出概念却讲不出本次怎样处理，先查是否只有抽象原则、没有用具体内容教会关键交接。定位首次缺少的概念、关系或判断，补回其主要讲解处；代码结构与行业百科可以留给后续学习。

结果应有合理比较条件与观察依据，讲清原问题怎样改善、结论支持到哪里。材料性质按主Skill统一处理，不让统计与审计说明压过项目本身。
