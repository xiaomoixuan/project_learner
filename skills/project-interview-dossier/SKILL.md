# 完整项目学习手册

帮助不了解、只参与局部或没有做过项目的读者，建立完整认知、掌握具体做法和判断，最后能够讲述。简历提供知识、动作和结果口径的覆盖依据，正文不逐句翻译，不以面试问题作为章节。

未给出的业务、流程、实现、阶段、协作和数据，主动补成一套现实可行的教学方案，保留用户明确约束。没写不等于没做，不要求用户证明经历或确认内部细节。开头集中说明教学重构性质，不能把补建材料声称为查证过的企业记录。

## 材料与统一项目

读取原简历、用户选择的项目和方向，以及实际提供的JD。不能辨认且影响方案的文字，先换提取或视觉方法核对；不重复索取已经提供的信息。JD可选，用户要求直接做时不等待，不补造JD。

尚未提供JD且未明确跳过时，使用宿主可用的用户输入/选择工具（如 `request_user_input_async` 或当前模式可用的 `request_user_input`）询问一次：“可以粘贴目标岗位的JD；没有也没关系，可以用自然语言描述岗位或求职方向。”提供“粘贴JD”“没有JD，描述岗位”“跳过，按已有信息继续”选项，允许自由文本输入。工具不可用时用普通对话询问；已提供、已跳过或要求直接开始时不再问。

将原简历或忠实转录、实际JD单独保存为原始提问输入，不混入作者情境、范围摘要或知识清单。用户选定项目属于调度指令。

一个主作者依据[项目底稿](references/project-blueprint.md)补建业务对象、原有基础、完整业务、目标、团队、我的位置、实施与交付状态。底稿保持轻量，专业事实只核查会影响方案的不确定处。公开资料支持背景与原理，不证明内部实施。

## 主流程：先设计教材，再写完整工作

1. 提取必须覆盖的知识、动作、选择和结果，连同必要上下游建立内部清单，不输出逐句映射。
2. 读取[六板块规范](references/document-guide.md)，生成项目专属目录。正文顶层依次为：项目背景与目标；业务流程与产品全貌；整体方案与基础知识；项目推进与核心工作；验证、迭代与交付；项目复盘与学习巩固。六部分可含多个章节，内部小标题按实际项目安排。
3. 在后台给每章确定学习目标、前置知识、内容、演示材料、产物和下一章联系。检查概念先后、工作完整性、覆盖与重复。已有服务不套从零开发，非软件项目不强造系统界面。
4. 按[教学方法](references/teaching-method.md)、[岗位重心](references/role-focus.md)与[深度标准](references/depth-standard.md)连续写作。主要工作展示可读的具体材料，解读其中影响处理的内容，再展开起手操作、中间变化、核查取舍、成品与接收人的实际使用。不能从材料直接跳到结论、从修改前跳到修改后，或只交名称与空模板；各项主要工作分别讲透。归纳的是材料到工作的教学关系，不固定示例的步骤、小标题、数量或参数；背景与原理按自身学习职责展开。
5. 背景和原理直接说明；我的行动、判断、协作、交付和复盘用“我”，其他成员保留职责。标题直接说明主题，删除描述作者排文章的伪行动和生硬压缩句。数字先解释对象与口径，再展示和解读，具体自洽但不堆数据。
6. 按[质量检查](references/quality-checks.md)从头读成品，完成结构、语言、机制与数字自查。仅用正文材料实际复走主要工作，留下中间结果及产物；卡住就将材料、操作或判断补回第一次需要处，再换一个关键条件检查能否迁移。提炼讲述和可返回具体教学位置的复习路线。需要对照实验时，此时冻结直接生成版，尚未接收interview题目或反馈。

## 内部interview：独立出题、作答与回填

默认先完成六板块教材和正常自查，不把interview作为每次必经。出现以下情况时启用：用户明确要求追问/充分性审查；读者反馈主要工作无法复做；正常自查后仍有具体材料、步骤、判断或交接缺口；指标、风险决定或跨机制归因仍存在不能复判的跳跃。不能仅因篇幅长、术语多、采用RAG或多模块就启动全套。缺口能够直接修正时先补教，再判断是否仍需独立检查。

启用后仍使用既有协议的三个独立视角和同人复验，不在没有对照证据时承诺减少代理仍有同样效果；不启用时如实写“主作者自查完成”，不声称通过独立interview。维护实验可据新证据调整策略；用户已明确要求时必须执行，不能用自查冒充。

启用时启动[内部interview](internal/interview-auditor/SKILL.md)三个不继承作者上下文的新实例，可与写作并行。它们的项目材料只能是原简历/忠实转录和实际JD，系统仅提供模块、镜头、用户选定项目及输出要求。不给作者情境、目录、正文、自评或其他问题。

A关注业务、贡献、协作和选择；B关注操作、机制、依据和异常；C关注解释、条件变化和深入追问。各自直接出题并冻结，不等用户回答。JD后补保留原题，另存原始输入批次追加，最终各批检查同一正文。无题数配额。

冻结后，同三位读取完整正文，逐子问实际作答并引用具体依据，按通过、过浅、缺失、冲突判定。C先顺序读，再做迁移；目录散乱、语言生硬、概念或操作跳步也属于教学问题，不能因专家能搜索出答案就通过。

主作者把真实缺口集中融回对应章节，同步相关流程、例子、结果和讲述。问题不反过来提供目录，不以增加问答附录代替教学。原检查者复答未通过及受影响题，未受影响题核实依据后绑定新版本。不得删题、改弱、缩范围或平均分放行；充分正文前提允许明确推导。

验收状态、JD批次、记录历史与完成条件按[验收协议](references/acceptance-protocol.md)。工具中断保留待验状态，不声称独立通过；同三位负责复验，不另增重复团队。

## 维护时的版本对照

仅在用户要求或维护验证时读取[对照实验](references/comparison-protocol.md)。保留直接生成版和interview改进版，由另一位全新上下文代理匿名比较实际可学性，先冻结质量判断，再看来源和成本，决定保留必经、改为按需或取消默认强制。普通教材不默认运行额外比较代理。

## 交付

默认完整Markdown手册，前置使用说明和可读目录，六板块正文层级清楚，末尾给练习、讲述、复习路线、必要来源及配套记录链接。完整问题、答案、版本和历史另存；正文无裸HTML、哈希、内部注释或长篇验收表。

亲自读取最终成品；指定导出格式时遵循相应工具规范并查看实际显示。无默认字数上限，自主连续完成，不逐章审批或要求用户不断说继续。
