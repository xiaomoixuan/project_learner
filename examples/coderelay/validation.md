# CodeRelay 示例的验证与前后对比

本页归纳实际完成的验证，完整私人输入和逐轮实验记录不随示例公开。更完整的维护历史见仓库的[验证说明](../../VALIDATION.md)。

## 手册怎样形成

固定原始简历、实际岗位职责及生成任务，先做六轮独立生成与新读者评审。每轮作者只读取当轮 Skill 和原始输入，不接收旧稿、旧评价或预设答案。之后由独立比较者匿名比较旧版与第六轮直接生成版。

匿名比较认为新版更适合首次学习，改善主要在产品认识、完整使用和信息交接；旧版部分机制解释仍更深。针对深度损失的局部新旧 Skill 试验总体持平，新增规则没有证明收益，已撤回。随后整合局部重新生成的材料并做普通修订。

本目录公开的是完成这些整合、普通修订和最后 interview 回填的成品，不是未经编辑的 Skill 单次直接输出。不能把全部成品收益归于 Skill 独立生成。教学正文沿用已经受验的版本，公开时只替换末尾的材料链接。

## 最后一次新读者评审

新的读者 Agent 仅收到完整成品、实际岗位职责和原阅读任务，不接收题集、旧评价或作者历史。它按初次接触项目及 Agent/RAG 机制的约束，顺序学习并实际复述项目和代表功能。

| 维度 | 分数 | 实际理解依据 |
| --- | ---: | --- |
| 内容深度 | 9 | 能解释依赖调度、信息交接、检索失败位置、记忆更新和写操作结果未知的处理 |
| 可理解性 | 9 | 能从产品使用讲到后台机制；术语在需要时解释，双路检索的暂缓问题在后文得到解决 |
| 语言自然度 | 8.5 | 主要叙述清楚，但第四、五板块较密，评测部分需要慢读 |
| JD 适配 | 9 | 能将架构、规划、工具、记忆和工程迭代连接到研发协作任务 |
| 整篇连贯性 | 9 | 同一任务贯穿用户过程、机制、开发和验证，能处理新提交等相邻变化 |

总体判断为“很好”，没有未解决的理解阻塞。维护者此前额外设定的“五项均至少 9 分”门槛未达到；它并非用户要求，已明确修正为依据实际理解、关键阻塞和总体判断评估，原分数和记录保留。这里没有把语言 8.5 改写成 9。

这是代理约束阅读，不是真人学习效果实验，也不核验真实工程实现。读者指出，具体情境和部分实现属于教学重构，转述个人经历时仍应对照实际工作；正文开头和结果章已说明其身份。

## 最后单独运行的 interview

按用户节省时间的要求，只启动一个全新审查实例。它先仅依据原始简历、实际 JD 和模块冻结 28 题，再读取正文实际作答。首轮 27 题通过，S-19 过浅；修补原 5.1、5.2 后由原实例复验，28 题全部通过。原题、原失败和复验历史都保留。[实际问题与最终复答](interview.md)另存，没有将题集塞进手册正文。

S-19 修补前，读者只知道“业务硬规则单独检查，综合指标辅助看趋势”；修补后，正文解释了如何用另一组正反样例形成标尺、固定评价方式与门槛，再进行 Top-K 对照。若分数全过而漏掉关键条件，该题仍失败；若规则通过但指标未过，则回查样例和评价方式，再按同一口径验证。没有新增真实实验数字。

## interview 前后是否改善

另一个未参与写作或 interview 的比较者，先依据原始输入冻结五项学习与五项迁移任务，再分别顺序读匿名全文、保存独立作答和质量结论。来源与成本在结论冻结后才揭示。

| 比较内容 | 结论 |
| --- | --- |
| 产品全貌与正常使用 | 持平，两版均能解释主要功能、结果与个人范围 |
| 检索、记忆、规划、工具和执行 | 持平，核心机制与相邻变化的教学支持相同 |
| 评价门槛与验收方法 | interview 后有局部增益，能解释标尺怎样形成及如何处理不同信号 |
| 语言与阅读负担 | 主体相同，新增评测解释增加该节密度 |
| 整体判断 | 核心教学基本持平，不能宣称整篇明显进步 |

单实例审查为 1 个出题、1 个审查、1 个同人复验调度轮次；墙钟约 10 分 55 秒，含主作者回填与调度，不是纯推理时间。Token、API 请求数和金额不可得，三个调度轮次不等于三次 API 请求。额外比较和最终读者属于维护实验，部分阶段并行，耗时不相加。

本案例支持继续按具体缺口启用 interview。没有等量作者额外投入的对照，不能证明所有局部收益均由该方法产生，也不能外推到所有项目、岗位或学习者。
